# 기억나무·열매 돌봄 보상 리팩터링

## 무엇을 만들었는지

- 청소 미션 완료마다 소비되지 않는 돌봄 포인트 3점이 현재 기억나무에 자동으로 쌓이도록 바꿨다.
- 3·6·9·12·15포인트의 새싹·작은 나무·꽃·작은 열매·잘 익은 열매 상태를 텃밭 그래픽으로 표현했다.
- 15포인트마다 다섯 기록을 가진 완성 나무를 과수원에 영구 보관하고, 다음 나무가 자동으로 시작되도록 구현했다.
- 완성 열매와 현재 나무를 누르면 날짜·공간·미션·모드·NORMAL 애프터 사진·사진 관찰/안내 요약을 보는 기록 패널을 만들었다.
- 완성 열매마다 포인트를 소비하지 않는 `이번 열매의 돌봄 혜택` 제품군 선택과 쿠팡 검색 연결을 만들었다.
- 텃밭 오른쪽의 단계 목록·긴 설명 패널을 없애고, 넓은 그래픽과 작은 정보 바·단일 CTA로 정리했다.

## 문제·막힌 지점

- 기존 텃밭은 미션마다 랜덤 새싹이 각 밭에 늘어나고, 성장 단계 설명과 예전 농장 구조가 화면을 차지해 실제 돌봄 기록과 연결되는 감각이 약했다.

## 직접 원인과 근본 원인

- 성장 기준이 현재 완료 수와 랜덤 작물 배열에만 묶여 있어, 나무 하나가 어떤 청소 기록으로 자랐는지 보관할 데이터 구조가 없었다.
- 기존 기억의 조각은 과거 상점·수확 흐름과 같은 잔여 포인트 구조를 사용해, 누적·비차감 보상이라는 새 경험을 표현할 수 없었다.

## 해결

- 로그인별 `localStorage`에 `totalCarePoints`, `activeTreePoints`, `activeTreeRecords`, `orchardTrees`를 가진 돌봄 숲 데이터를 추가했다.
- 기존 완료 기록은 최초 진입 시 새 나무·과수원 구조로 옮겨 기존 기록을 잃지 않게 했다.
- 열매 혜택은 `benefitId`, `benefitType`, `benefitTitle`, `benefitDescription`, `productQuery`, `couponCode`, `selectedAt`, `expiresAt` 필드를 저장하고, MVP에서는 `product_link`만 사용한다.
- Supabase 청소 가이드 조회·사진 분석·NORMAL 제품 추천은 변경하지 않았다. 애프터 사진 썸네일도 계속 브라우저에만 저장한다.

## 남은 위험과 제한

- 혜택은 쿠팡 검색 링크만 제공하며 실제 할인 쿠폰·제휴 추적·결제는 연결하지 않는다.
- 브라우저 저장소를 사용하므로 같은 계정이라도 다른 기기에는 자동 동기화되지 않는다. Supabase에는 개인 기록·포인트·사진을 저장하지 않는다.
