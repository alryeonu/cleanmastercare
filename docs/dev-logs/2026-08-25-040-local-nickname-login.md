# 닉네임 기반 로컬 로그인과 농장 저장

## 무엇을 만들었는지

- 닉네임과 정확히 4자인 비밀번호로 시작하는 간단한 로그인 화면을 추가했다.
- 로그인한 닉네임 뒤에 초록색 하트를 상단에 표시했다.
- 포인트, 적립 내역, 돌봄 농장, 씨앗, 조경, 농부 꾸미기, 기록, 완료 장소를 닉네임별로 분리해 브라우저에 저장했다.
- 기존 브라우저의 공용 저장 기록은 첫 로그인 계정으로 한 번만 옮겨 기존 포인트와 농장 진행 상태를 보존했다.

## 문제·막힌 지점

- 기존 앱은 모든 상태가 하나의 localStorage 키에 저장되어 같은 브라우저에서 사용자를 구분할 수 없었다.
- Vercel 서버는 상태를 영구 보관하지 않으며, 현재 Supabase는 검수된 청소 지식 전용으로 유지해야 했다.

## 해결

- 계정 목록·현재 로그인 세션은 별도 localStorage 키에 저장하고, 행동 기록 키에는 닉네임별 프로필 접미사를 붙였다.
- 비밀번호 원문은 저장하지 않고 브라우저 Web Crypto의 SHA-256 해시만 저장해 동일 닉네임의 재로그인을 확인한다.
- 사진 원본은 기존과 마찬가지로 저장하지 않고, 사진 비교 중복 방지용 해시만 프로필별로 유지한다.
- 로그인 정보와 행동 기록을 Supabase 또는 서버에 전송하지 않았다.

## 실행한 테스트와 실제 결과

- `py -B -m pytest -q -p no:cacheprovider`: 33 passed.
- `node --check static/app.js`: 성공.
- `node --check static/room3d.js`: 성공.
- `node --check static/room-canvas3d.js`: 성공.
- 실제 브라우저에서 로그인 창, 4자 비밀번호 입력 제한, 닉네임·초록 하트 영역을 확인했다.
- 360px·768px 화면에서 로그인 창이 가로 스크롤 없이 표시됨을 확인했다.

## 남은 위험과 제한

- 이 로그인은 같은 브라우저·같은 기기에서 상태를 나누어 보관하는 방식이며, 다른 기기와 자동 동기화되지는 않는다.
- 브라우저 사이트 데이터를 삭제하면 해당 기기의 로그인과 저장 기록도 삭제될 수 있다.
