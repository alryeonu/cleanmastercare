# 기억의 조각과 기억나무 보상

## 무엇을 만들었는지

- 사용자 화면의 `포인트` 명칭을 `기억의 조각`으로 바꿨다.
- 씨앗 상점과 씨앗 구매 단계를 제거하고, 기억의 조각 1개를 농장 자리에 바로 심도록 변경했다.
- 기존 네 작물을 `햇살나무`, `응원나무`, `꽃나무`, `열매나무`로 바꾸고 성장 단계도 나무 형태로 정리했다.
- 기존 포인트 잔액은 같은 저장 키를 유지해 기억의 조각으로 이어지게 했다.
- 예전에 구매한 씨앗은 구매 당시 비용만큼 기억의 조각으로 한 번만 되돌리는 프로필별 마이그레이션을 추가했다.
- 미션 보상, 중복 지급 방지, 농장 성장과 해금 상태의 기존 저장 계약은 유지했다.

## 문제·막힌 지점

- 기존 흐름은 행동 보상으로 포인트를 받은 뒤 씨앗 상점에서 다시 씨앗을 사야 해, 청소 미션과 농장 성장 사이에 불필요한 단계가 있었다.
- 이미 씨앗을 구매한 사용자의 저장 상태를 단순 삭제하면 사용한 보상이 사라질 수 있었다.
- 개발일지 템플릿 경로가 저장소에 존재하지 않아 가장 최근 완료 일지의 형식을 기준으로 기록했다.

## 직접 원인과 근본 원인

- 직접 원인은 농장 심기 동작이 별도 씨앗 재고와 상점 구매 함수에 의존한 것이었다.
- 근본 원인은 보상 단위와 농장 성장 재료가 분리되어, 사용자가 기대한 `미션 완료 → 나무 성장` 관계가 약해진 것이었다.

## 해결

- 기존 잔액 저장 계약을 유지하면서 표시와 안내를 기억의 조각 중심으로 통일했다.
- 별도 씨앗 재고 확인과 구매 UI를 제거하고, 심기 시 기억의 조각 1개를 직접 사용하도록 변경했다.
- 레거시 씨앗 수량에 기존 가격을 적용해 조각으로 복구하고, 마이그레이션 완료 표식을 저장해 중복 환급을 방지했다.
- 사용자의 최신 요청을 기준으로 PRD의 보상·농장 요구사항과 수용 기준을 함께 갱신했다.

## 남은 위험과 제한

- 브라우저에 저장된 과거 씨앗이 있는 경우 첫 로그인 시에만 조각 환급 이벤트가 생성된다.
- 조각으로 심은 나무는 기존 프로필별 로컬 저장 방식에 따라 현재 브라우저에 보존된다.

## 다음 작업과 다음 세션의 첫 행동

- 다음 작업은 사용자의 후속 요청을 기준으로 정한다.
- 농장 보상 변경 시 첫 행동으로 `STORE.cash`, 나무 슬롯 상태, 일일 보상 중복 방지 계약이 유지되는지 확인한다.

## 다음 세션이 확인할 파일과 회귀 주의사항

- 확인 파일: `static/index.html`, `static/app.js`, `static/styles.css`, `test_rules.py`, `PRD.md`.
- 씨앗 상점이나 씨앗 구매 단계를 다시 노출하지 않는다.

- 미접속 때문에 기억의 조각이나 나무 성장 상태를 감소시키지 않는다.
