# 게시글 팝업과 익명 댓글

## 무엇을 만들었는지

- 이야기 목록 카드에서 댓글 수와 댓글 입력칸을 표시하지 않도록 유지하고, 카드 전체를 누르거나 키보드 Enter·Space를 누르면 글 상세 팝업이 열리게 했다.
- 팝업에 글의 주제·제목·전체 본문·작성 시각, 기존 익명 댓글, 익명 댓글 작성 폼을 추가했다.
- 게시글 상세 조회와 익명 댓글 등록 API를 추가했다.
- 댓글은 이름·비밀번호·사진 없이 본문과 표시 시각만 저장하며, 게시글과 같이 서버 메모리에서만 유지된다.

## 문제·막힌 지점

- 목록 카드 안에 삭제용 controls가 있어 카드 전체 click 처리와 충돌할 수 있었다.
- 기존 익명 게시판은 새 게시글만 메모리에 저장하고 댓글 구조가 없었다.

## 직접 원인과 근본 원인

- 목록 조회 API가 카드에 필요한 게시글 정보만 반환했고, 상세 thread와 댓글을 조회할 데이터 계약이 없었다.
- 카드와 내부 control의 event 전파 경계를 정하지 않았다.

## 해결

- `data-open-post`를 카드에만 붙이고 삭제 영역에서 발생한 click/keydown은 상세 열기 처리에서 제외했다.
- `GET /api/community/posts/{post_id}`는 글과 comments를, `POST /api/community/posts/{post_id}/comments`는 검증된 익명 댓글만 반환하게 했다.
- 댓글은 2~300자로 제한하고, 게시글 삭제 때 해당 게시글의 메모리 댓글도 함께 제거한다.

## 실행한 테스트와 실제 결과

- `py -m pytest -q`: 28 passed.
- `node --check static/app.js`: 성공.
- thread 조회에 기존 익명 댓글이 포함되고 card API에는 `comment_count`가 없음을 확인했다.
- 익명 댓글이 id·본문·시각만 반환되며 2자 미만 입력은 거부됨을 확인했다.
- 정적 계약으로 카드 click/keyboard 상세 열기와 댓글 수 메타데이터 부재를 확인했다.

## 남은 위험과 제한

- 게시글과 댓글은 서버 재시작 시 초기화되는 MVP 메모리 데이터다.
- 댓글 삭제·신고·정렬은 이번 범위에 포함하지 않았다.
