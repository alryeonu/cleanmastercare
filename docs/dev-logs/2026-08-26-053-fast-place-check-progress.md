# 빠른 계획 장소 사진 확인과 진행률

## 무엇을 만들었는지

- 주간 계획의 비포 사진은 욕실로 고정 판정하지 않고, 오늘 계획한 장소(예: 싱크대)와 사진 속 장소가 일치하는지 확인하도록 바꿨다.
- 사진 확인 대기 화면에 0%부터 표시되는 진행률 막대와 퍼센트 안내를 추가했다.
- 계획 사진 확인은 브라우저 12초, OpenAI 요청 10초 제한으로 줄였다.

## 문제·막힌 지점

- 싱크대 일정에서도 욕실 사진 여부를 확인해 사용자에게 현재 계획과 맞지 않는 안내가 나타났다.
- 기존 35초 대기와 퍼센트 없는 로딩 화면은 사진 확인이 멈춘 것처럼 느껴졌다.

## 해결

- `cleaning_area` 분석 결과의 `area_hint`를 계획 장소와 비교하고, 불일치·불확실·시간 초과 시 해당 장소 사진을 다시 올리도록 안내했다.
- 진행률은 실제 응답 완료 전까지 92%까지만 표시하고, 응답 또는 시간 제한 시 로딩을 반드시 닫는다. 이는 정확한 서버 처리율이 아니라 기다림의 예상 진행 상태를 보여 주기 위한 UI다.
- 청소 절차는 기존처럼 FastAPI를 거쳐 Supabase의 검수된 데이터로 조회하며 DB 구조나 데이터는 변경하지 않았다.

## 남은 위험과 다음 작업

- 사진 구도가 좁거나 장소 단서가 적으면 빠르게 재등록 안내로 전환될 수 있다. 실제 모바일 사진과 싱크대·책상·침대·신발장 일정의 인식 결과를 배포 환경에서 확인한다.
- 다음 세션에서는 `static/app.js`의 계획 장소 확인, `server.py`의 10초 OpenAI 제한, 그리고 Supabase 청소 절차 조회 회귀를 함께 확인한다.
