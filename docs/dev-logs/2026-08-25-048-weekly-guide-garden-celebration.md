# 주간 청소 절차와 돌봄농장 완성 연출

## 무엇을 만들었는지

- 주간 계획의 비포·애프터 사진 입력 칸에서 선택한 사진을 현재 화면에 즉시 미리보기로 표시했다.
- 비포 사진 뒤 `/api/cleaning-guide`를 호출해 Supabase에서 조회한 검수 절차를 최대 6단계까지 상세 문안으로 보여 주도록 했다.
- 지식 DB 경로가 사용할 수 없을 때에는 이를 Supabase 절차로 표시하지 않고, 기존의 기본 절차로 계속할 수 있게 구분했다.
- 전후 사진에서 같은 장소의 관찰 가능한 개선이 확인되면 텃밭으로 즉시 이동하고 반짝이는 연출을 표시한다.
- 첫 개선 확인에는 토마토·딸기·바질·당근 중 하나를 무작위로 고르고, 집·길·울타리·네 칸의 사각 밭으로 구성한 돌봄농장 안에서 새싹과 작물이 자라게 했다.
- 새싹 아래의 작물명·단계 캡션은 숨겨, 밭 안의 식물 자체가 성장 상태를 표현하도록 했다.

## 문제·막힌 지점

- 기존 주간 계획은 사진을 고른 사실만 표시하고 미리보기를 보여 주지 않았으며, 상세 절차가 네 단계로 잘려 있었다.
- 모든 API 응답을 Supabase 안내로 표기하면 장애 대체 절차까지 DB 결과처럼 보일 수 있었다.
- 로컬 8005 포트에는 이전 실행본이 이미 떠 있어, 별도 8006 포트에서 현재 코드의 환경변수·가이드 API를 확인했다.

## 해결

- 사진 데이터는 메모리 상태에만 두고 `<img>` 미리보기로 렌더링했으며, 저장소·기록·DB에는 사진 원본을 추가하지 않았다.
- 응답 `mode`가 `local_fallback`이면 기본 안내라는 표기와 설명을 사용하고, 그 외에는 Supabase 검수 절차 표기를 사용했다.
- 외부 쇼핑몰 추천·구매 링크와 실제 커피 쿠폰 발급은 PRD의 실제 상품·교환 제외 범위에 맞지 않아 추가하지 않았다. 기존의 앱 내 가상 꾸미기 보상 흐름은 유지한다.

## 테스트 및 결과

- `node --check static/app.js` — 성공.
- `py -B -m pytest -q -p no:cacheprovider` — 41 passed.
- `git diff --check` — 성공.
- `GET http://127.0.0.1:8006/health` — `supabase_configured: true` 확인.
- `POST http://127.0.0.1:8006/api/cleaning-guide` — `desk` 입력에서 로컬 대체 안내와 출처가 반환되어, DB 경로 실패 시에도 안내가 계속되는지 확인.

## 다음 작업 시 참고

- 사용자 사진은 미리보기 중인 메모리에만 존재해야 하며, `localStorage`와 Supabase에는 저장하지 않는다.
- 배포 환경에서는 `SUPABASE_URL`과 `SUPABASE_SECRET_KEY`를 유지해야 검수 절차를 조회한다.
- 새 공간의 발행 절차가 아직 없는 경우 UI가 기본 안내로 전환되는 동작을 보존한다.
